# 몬스터 로스터

스폰 테이블을 구성할 몬스터 종류 정의. 각 몬스터는 `MonsterDef`(설계 §13) + 행동 `MovementProfile`로
표현하며, 스폰 테이블의 `SpawnEntry`가 이들을 weight/cost로 섞는다(설계 §2).

> 진행: ① 이 md 로 로스터 확정 → ② SO 데이터 생성 → ③ 인지(FSM) 부여.
> 수치는 **잠정**(밸런싱 전). 장갑/데미지·특수능력·공격은 현재 스키마에 없어 **확장 제안**(§아래).

## 4. 스폰 테이블 구성

- 위 몬스터들이 적당히 섞여 **스폰 테이블 1개**가 됨. 스폰 테이블은 **여러 개** 필요(상황/난이도/테마별).
- `SpawnEntry { monster, weight, cost, groupSize, minDifficulty, tags }` 로 섞고, `cost`+예산이 난이도
  스케일링(초반 싸구려 스웜 → 후반 엘리트). 잠정 cost: 작은=1, 중간=3, 큰/중장갑=8, 소환수=10.
- 소환수는 스폰 테이블 안에서 또 다른 스폰 테이블을 참조 → **재귀적**(테이블 of 테이블).

## 5. 추가 시스템 (✅ 데이터/규칙 구현됨 — 실행은 후속 전투 단계)

아래는 데이터·규칙(SO/순수 로직)으로 구현 완료. 실제 데미지 적용·공격 실행·약점타격·소환은 후속:

1. **장갑 / 데미지 타입** — "특정 공격만 데미지"(중장갑)를 위해:
   - `Armor` enum: None / Light / Heavy
   - `DamageType` enum: Normal / Piercing(관통) / Explosive(폭발) / WeakPoint(약점)
   - 규칙: Heavy 는 지정 `vulnerableTo` 타입(예: Piercing/WeakPoint)만 데미지, 그 외 ~0.
   - **약점 부위**(부위파괴와 연결): 중장갑 몹은 약점 콜라이더 보유 → WeakPoint 데미지.
2. **특수 능력(Ability)** — `canStrafe/canBackstep` 만으론 부족. `MonsterAbility` 추가:
   - `Leap`(도약 접근 공격), `Burrow`(잠복 후 플레이어 근처 재출현), `Summon`(하위 테이블 소환).
   - [Flags] enum 또는 Ability SO 리스트(능력별 파라미터 필요 시).
3. **공격 정의(CombatProfile/AttackDef)** — `attackKind` 단일론 부족(폭발+기관총 동시 등):
   - per-attack: 종류(Melee/Projectile/AoE/Sustained/Leap), 데미지, 사거리, 쿨다운, 텔레그래프(예고),
     AoE 반경, 투사체 속도, `DamageType`.
   - 몬스터는 attack 여러 개 보유 가능(포대형 = 폭발 + 기관총).
4. **소환(Summon) 메커니즘** — 소환수가 참조할 스폰 테이블 + "안 보이는 곳 스폰" 규칙(설계 §7 후보점
   알고리즘 재사용) + 빠른 접근.

> 도망 안 함은 기존 `canFlee=false`로 표현 가능(중장갑은 false). 키터(원거리 작은놈)는 `preferredRange`
> 로 거리 유지. 이 둘은 추가 없이 됨.
